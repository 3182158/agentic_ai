Help-Desk RAG: Ingestion & Retrieval Pipeline

How Acme policy documents (Markdown, PDF, Word) become searchable chunks in SQLite, and how a question turns into a grounded, cited answer. Click any step for details.

Part 1 · Ingestion (offline, re-runnable)

help-desk-rag/ingest.py — run with python help-desk-rag/ingest.py [--rebuild]

SQLite store — .data/rag/rag.sqlite3

chunks
node_id PK, doc_id, text, metadata_json, embedding (BLOB, 1536 floats)
documents
doc_id PK, source_id, version, file_hash (SHA-256), ingested_at
meta
key/value, e.g. embed_model = text-embedding-3-small. A different model is refused without --rebuild.

Side cache: .data/rag/parsed/<file-hash>.md holds LlamaParse output so unchanged PDF/DOCX files are never re-parsed (saves API cost). It is a cache, not the search index.

Chunking in detail

Stage 1: by heading
MarkdownNodeParser: each #/## section is one chunk, so one policy rule stays together. Heading path becomes the section metadata.
Stage 2: size cap
SentenceSplitter: sections over 512 tokens are split on sentence boundaries with 64 tokens of overlap.
What is embedded
Chunk text plus heading. Fields like source_id, version, owner are stored for citations but excluded from the embedding and the LLM view.
